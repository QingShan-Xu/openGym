4. 由助手亲自撰写 `{ "动作id": ["中文步骤", ...] }` JSON 批次，写入临时文件。不得用通用模板替代实际步骤，不调用翻译模型/API，不读取或处理动作图片与视频。

7. 完成后运行 `check`、`node scripts/catalogue/build.mjs`、动作目录检查、中文覆盖测试、完整前端测试及构建。测试使用 `TZ=UTC NODE_OPTIONS=--no-experimental-webstorage`。
8. 更新 docs/CHINESE.md、PR 描述和任务进度；提交、推送到用户 fork 的功能分支。没有获准合并 main，不向上游提 PR。

## 中文表达规则

- 直接讲清起始姿势、移动哪一侧/哪一肢、运动方向和终点、如何回到起点。
- brace/engage core：收紧核心或腹部，不能写成“支撑核心”。
- shoulder blades：肩胛骨；squeeze together：向中间收拢，不能“挤压肩刀”。
- band：弹力带；barbell：杠铃；dumbbell：哑铃；kettlebell：壶铃；cable：绳索；bench：训练凳。
- reps：次数/重复；set：组；lunge：弓步；hinge：从髋部折叠俯身；drive through heel：用脚跟蹬地发力，不能“开车穿过脚跟”。
- 结合完整动作解释 lower/return/press/hold 指的是什么，而非统一写“降低/返回/按压/保持”。
- 保留左右、角度、时间、次数、呼吸、不要锁死关节、控制幅度等实际提示，不添加原文无依据的动作限制。
- 如果名称和步骤存在矛盾，记录具体 id 与疑点，不能无声更改动作机制。语言表达可澄清原文有依据的指代。
- 本任务由助手完成上下文校对与自动结构校验，不能宣称已由健身专业人员或母语人士独立审核。
